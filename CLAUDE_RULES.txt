Claude Code 工作原则（2026-05-31）

1. 工具使用优先本地
   需要调用工具时，优先在本地环境寻找可用方案或已有实现；本地找不到时，才考虑下载或引入新依赖。

2. 需求先分析，后实施
   用户提出需求后，不立即修改代码。先分析可行方案，向用户呈现方案选项及利弊，由用户选择确认后再执行。用户的方案选择需保存到本地文件备查。

3. 使用 Git 提交文件
   代码修改完成后，判断是否可以 git 提交；可以提交时，及时 commit，确保随时可以回退到之前的状态。不强制推送远程，但要求本地有清晰的提交历史。

4. 大 API 变动需记录文档
   当发生较大的 API 变动（如新增/删除路由、修改接口字段、调整数据库表结构等）时，必须同步记录文档，说明变更内容、原因及迁移方式。

5. 用户输入保存本地
   用户在方案选择、需求确认、关键决策环节的输入，应保存到本地文件（如 decisions/ 目录或相关日志），以便后续追溯和复现上下文。

6. 写代码时添加详细调试日志，以便后续检查bug，遇到用户反映bug，禁止猜测，根据调试日志进行分析。

7. 思考过程始终使用中文，禁止绕圈子式思考。

8. 记录工具使用错误与改正方案
   使用各类工具（部署脚本、AI API、npm、数据库操作等）过程中发生的错误、踩过的坑及其最终改正方案，应记录在此文档或独立的错误日志中。目的是后续遇到同类问题时能直接参考，避免重复踩坑。

9.此文档为最重要文档，compact时需保留信息。

## 技术决策记录

### AI 模型选型：必须使用多模态模型（2026-06-05）

**结论**: 本项目必须使用多模态/视觉模型（如 GLM-4V、GPT-4V），不适合纯文本模型。

**依据**: 30+ 个 AI 调用点中有 7 个核心功能依赖图片输入（OCR 文档识别、题目图片、AI 助手图片分析、图片知识树生成等），换纯文本模型会导致这些功能完全失效。详细分析见 WORKSPACE_SUMMARY.md "AI 模型选型分析"章节。

**成本优化建议**: 采用混合策略——检测消息中是否含图片，有图片时调用 vision 模型，纯文本时调用更便宜的文本模型。
